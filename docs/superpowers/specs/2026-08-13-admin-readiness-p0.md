# مواصفة جاهزية واجهة المسؤول — P0

> **Status:** BINDING / IMPLEMENTED on `main` @ `c3b17a7` (2026-08-13).

## الهدف

إغلاق الفجوات التي تمنع المسؤول غير التقني من إدارة العمل ضمن التجمع أو المنشأة أو الوحدة، من دون إعادة تصميم نموذج الصلاحيات أو إضافة موديولات أعمال جديدة.

## الحدود

- يبقى المنتج Task-only: المهام، المنظمة، الهوية، الصلاحيات، والخدمات المساندة المحتفظ بها.
- تبقى أنواع النطاق `cluster | facility | unit | record_set`.
- سياق الجلسة لا يمنح صلاحية؛ كل صف في قائمة إدارية يمر عبر Authorization وRecordFacts.
- `docs/contracts/api/openapi.yaml` هو مصدر الحقيقة، والملفات المولدة لا تعدل يدويًا.
- لا يطبق W27 على إنتاج في هذا العمل. النسخ الاحتياطي وتجربة الاستعادة أدلة تشغيلية خارج المستودع.

## عقد المهام

### إنشاء وتحديث

- يعرّف `TaskCreate.owner_organization_unit_id` كـUUIDv7 اختياري.
- تكون الأولوية في الإنشاء والتحديث والاستجابة: `low | normal | high | urgent`.
- تزال عبارة source-linked؛ المهام مستقلة بعد تقاعد Work Management.

### قائمة المهام

`GET /tasks` يدعم:

- `view=mine` افتراضيًا: السلوك الحالي (منشئ، مكلّف، أو مشارك).
- `view=scope`: قائمة إدارية ضمن نطاق محدد.
- مع `view=scope` يلزم `scope_type=cluster|facility|unit` و`scope_id=<UUIDv7>`.
- وجود `scope_type` أو `scope_id` مع `view=mine`، أو نقص أحدهما مع `view=scope`، يرجع 400.
- قبل تعداد الصفوف، يبني الخادم RecordFacts للنطاق ويطلب `tasks.read`؛ الممنوع يرجع 403 حتى لو كان النطاق فارغًا.
- `cluster` يشمل المنشآت والوحدات التابعة، و`facility` يشمل المنشأة ووحداتها، و`unit` يطابق الوحدة نفسها فقط.
- بعد تضييق المرشحين بنطاق الملكية، يظل كل صف يمر عبر قرار `tasks.read` الفعلي.

### عرض الأسماء

كل مهمة معادة للواجهة تحمل، عندما تتوفر البيانات:

- `owner_scope: { scope_type, scope_id, label, code? }`
- `assignee: { user_id, display_name }`
- `creator: { user_id, display_name }`

تبقى معرّفات المستخدم الحالية للتوافق، لكن الواجهة تعرض الاسم البشري أولًا. حل الأسماء يتم عبر Contracts منشورة من Identity وOrganization، ولا تقرأ Tasks جداول موديول آخر.

## عقد إدارة الصلاحيات

`explicit-denies` مورد إداري منفذ؛ يجب إدراجه في enum الخاص بكل عمليات `/authorization/{adminResource}` في OpenAPI.

## الواجهة

- مدخل المنظمة يظهر عند امتلاك أي قدرة قراءة تنظيمية مستخدمة داخل الصفحة، لا عند قراءة التجمع أو المنشأة فقط.
- تبويب المسميات يستخدم القدرة الفعلية الجامعة `organization.position.read`، المتطابقة مع حارس الـAPI الحالي.
- تبويب العلاقات الإشرافية يستخدم القدرة الفعلية الجامعة `organization.unit.read`، المتطابقة مع حارس الـAPI الحالي.
- شاشة المهام توفر مبدلًا بشريًا: «مهامي» و«مهام نطاقي». خيار النطاق يظهر فقط لمن يمكنه اختيار نطاق متاح، ويستخدم الاسم لا UUID.
- لا تستنتج الواجهة السلطة من الدور أو نوع النطاق؛ الخادم هو الحارس.

## القبول

1. عقد OpenAPI يطابق التنفيذ ويعاد توليد Orval دون تعديل يدوي.
2. مسؤول منشأة أو تجمع مخول يستطيع قراءة مهام نطاقه، ولا يستطيع قراءة نطاق خارج منحه.
3. مستخدم عادي يحتفظ بسلوك «مهامي» ولا يمكنه تفعيل قائمة إدارية عبر query parameters.
4. قائمة المهام تعرض أسماء المكلّف والمالك التنظيمي عند توفرها، ولا تجعل UUID النص الأساسي.
5. مدير وحدة بقدرة `organization.unit.read` يرى مدخل المنظمة وتبويبي الهيكل والإشراف؛ وتبقى بقية التبويبات محجوبة بقدراتها الفعلية.
6. الاختبارات المركزة وarchitecture/contract generation تمر، ثم البوابات الأوسع قبل إعلان الاكتمال.
