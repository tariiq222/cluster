# Cluster Task-Only Workspace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Disable work-management (Work Definitions, Work Records, requests, approvals, Workflow) behind a central feature gate while making Tasks a fully independent module with a complete lifecycle, permissions, notifications, and AR/EN web journey — per the approved spec `docs/superpowers/specs/2026-07-28-cluster-task-only-workspace-design.md`.

**Architecture:** Laravel modular monolith (`apps/api/Modules/*`) + React/Vite SPA (`apps/web`). Single OpenAPI contract `docs/contracts/api/openapi.yaml` feeds Orval. The API gains `config/features.php` + an `EnforceWorkManagementFeature` middleware (409 mutation / 404 read / `work_management.history.read` escape hatch, zero side effects). Tasks drops its Workflow bridge, gets a Task-owned `CreateTaskHandler`, a full state machine in `TransitionTaskHandler`, in-transaction notifications via a new Notifications contract, and server-computed `allowed_actions`. The web app gates navigation/dashboard/routes on the principal `features` projection and gains a full tasks experience.

**Tech Stack:** PHP 8.3 / Laravel 13 / PHPUnit 12 · React 19 / TS ~6 / Vite 8 / Vitest 4 / Playwright 1.61 · Orval (fetch client, custom mutator `fetcher.ts`).

## Global Constraints

- `docs/contracts/api/openapi.yaml` is edited FIRST; Orval output (`apps/web/src/api/generated/cluster.ts`) and `.orval/api-reference.html` are generated, never hand-edited (spec §13).
- Disabled modules/tables/migrations/contracts/data are NOT deleted (spec §3). Only the Tasks→Workflow *bridge* code is removed from the active surface (spec §7).
- Feature-disabled mutation problem type is exactly `urn:cluster:problem:feature-disabled` with HTTP 409 `application/problem+json` (spec §4). Disabled reads return the existing non-disclosing 404 shape.
- Task lifecycle is exactly: `open→in_progress→blocked→in_progress→completed`, cancel from `open|in_progress|blocked`; `completed`/`cancelled` terminal (spec §6). Block/cancel need a non-empty reason; complete needs a non-empty note.
- Dynamic action route param is `taskAction`, never `workflowTaskAction` (spec §7).
- Every task mutation: `If-Match` optimistic concurrency; commands keep `Idempotency-Key` where the current command pattern requires it; notifications in the same transaction, recipients = creator+assignee+participants minus actor, deduplicated (spec §9).
- The browser `features` projection is a rendering hint only; the server enforces independently (spec §4).
- No screen calls Workflow/Work Record APIs when `work_management` is disabled (spec §10).
- Do not hand-edit `apps/web/src/api/generated/**`; run `npm --prefix apps/web run api:generate`.
- Do not hand-edit `docs/api/endpoints.md` / `rbac-matrix.md` (generated by `scripts/inventory-routes.py`).
- Full phpunit runs need memory: `php -d memory_limit=1G vendor/bin/phpunit` (repo convention).
- Feature tests simulate 401 with a bogus bearer token, never by omitting the token (repo convention).
- Commits: one per task, conventional format. No push.

## Design decisions locked during planning

1. **Problem URI:** new `feature-disabled` type uses the spec's URN verbatim; the 33 existing `https://cluster.example/problems/*` sites are untouched.
2. **Notifications:** new contract `Modules\Notifications\Contracts\RecordNotifications` (Notifications module owns the `notifications` table) consumed synchronously by Tasks handlers inside the same DB transaction. Recipients deduped, actor excluded.
3. **Reasons/notes:** block/cancel reasons and completion notes are persisted as `task_comments` rows authored by the actor inside the same transaction (no schema migration; they surface in the existing comments UI and E2E assertions).
4. **Bridge removal:** `POST /tasks/from-step/{stepId}` route, `TaskController::fromStep`, `CreateTaskFromWorkflowStepHandler`, `WorkflowStepExists` in `TaskHttpStore`, and `AdvanceWorkflowStep` in the completion path are removed. `CompleteTaskHandler` is folded into `TransitionTaskHandler` (complete becomes a transition). `StaleTaskVersion` is kept. Historical `workflow_step_id`/`source_*` columns stay for reads.
5. **Attachments:** `POST /tasks/{taskId}/documents` mirrors the WorkRecords document-link approach (Documents module owns links); task detail exposes linked attachments.
6. **Team-scope check for assign/reassign:** actor must hold `tasks.assign` AND the target user must belong to the actor's manageable organization scope, resolved via the Organization module's scope-descendants contract (same BFS resolver used elsewhere), mirroring existing controller capability-check patterns.

Middleware sketch (mirror `TaskHttpSupport`/`AuthorizationApi` problem shapes and the fixture-principal resolution used by controllers):
```php
final class EnforceWorkManagementFeature
{
    public function __construct(private readonly ResolveDevelopmentFixturePrincipal $principals) {}

    public function handle(Request $request, Closure $next): Response
    {
        if ((bool) config('features.work_management')) {
            return $next($request);
        }
        $isRead = $request->isMethod('GET') || $request->isMethod('HEAD');
        if ($isRead) {
            $principal = $this->principals->resolve($request);
            if (/* principal holds work_management.history.read — mirror the capability check used by an existing controller, e.g. via DecideAccess::evaluateOnly or the principal's capability list */) {
                return $next($request);
            }
            return response()->json([
                'type' => 'https://cluster.example/problems/resource-unavailable',
                'title' => 'Resource unavailable',
                'status' => 404,
                'detail' => 'لا يمكنك فتح هذا الطلب أو لم يعد متاحاً.',
            ], 404, ['Content-Type' => 'application/problem+json']);
        }
        return response()->json([
            'type' => 'urn:cluster:problem:feature-disabled',
            'title' => 'Feature disabled',
            'status' => 409,
            'detail' => 'إدارة العمل معطّلة حالياً؛ المهام هي مسار العمل الوحيد المتاح.',
        ], 409, ['Content-Type' => 'application/problem+json']);
    }
}
```
