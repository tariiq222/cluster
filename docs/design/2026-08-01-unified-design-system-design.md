# سبيكة: نظام تصميم موحّد + إعادة توزيع الصفحات

**التاريخ** 2026-08-01 · **الحالة** معتمدة · **المخرجات** [PAGES.md](PAGES.md) · [DESIGN-RULES.md](DESIGN-RULES.md)

## 1. القرار

يعتمد Cluster ثيماً موحّداً واحداً مبنياً على قالب [shadcn-admin](https://www.shadcn.io/template/satnaing-shadcn-admin): **Tailwind v4 + shadcn/ui + Radix**، بتوكنز القالب **بقيمها الأصلية دون تعديل**. يُحذف نظام التصميم اليدوي القائم وكل التعليمات المرتبطة به. وتُعاد هيكلة معمارية المعلومات من تجميع بالمورد إلى تجميع بالغرض.

## 2. المشكلة

ثلاث مشكلات متمايزة، ولكل منها دليل:

**أ. لا يوجد نظام تصميم — يوجد CSS متراكم.** `apps/web/src/styles/` أربعة ملفات و~870 سطراً، بتوكنز مخصّصة (`--color-primary: #293b85`) ومكوّنات يدوية في `src/ui/index.tsx`. لا وضع ليلي، ولا مصدر حقيقة خارجي يمنع الانحراف.

**ب. تعليمات التصميم متناقضة وبائدة.** `docs/analysis/15-web-client.md` يصف `AppShell.css` بـ864 سطر و`WorkspaceTabs.css` و`ui.css` — **وكلها محذوفة**. `AGENTS.md` يحيل إلى `src/shell/routes.ts` و`RouteAccessGuard` و`AppWorkspace` — **وكلها غير موجودة** بعد إعادة بناء الواجهة في `26ab2dc`. وسبيكة `2026-07-28-cluster-task-only-workspace` تقيّد المنتج على «المهام فقط» بما يناقض تغطية 205 عملية.

**ج. الصفحات مجمَّعة بالمورد لا بالغرض.** `docs/api/endpoints-table.md` يعدّ 47 «صفحة»، منها 11 صفحة تنظيمية منفصلة (المسميات، الوظائف، الأشخاص، التكليفات…) هي عملياً أوجه لسؤال واحد: من يعمل أين وبأي صفة. النتيجة تنقّل مفكّك، وفجوة بين ما يوفّره الـAPI وما تعرضه الواجهة.

## 3. الأهداف

1. مصدر حقيقة واحد لكل صفحة: غرضها، مسارها، نمطها، مخرجها المرئي، حالاتها، وendpoints الخاصة بها.
2. قوانين توحيد قابلة للفرض آلياً تمنع انحراف أي صفحة جديدة.
3. تصفية كاملة لتعليمات التصميم البائدة والمتناقضة.
4. إسناد كل عملية من 205 لصفحة واحدة، أو إعلانها صراحةً «خارج نطاق الواجهة».

## 4. خارج النطاق

- تنفيذ التبنّي البرمجي لـTailwind/shadcn — خطة منفصلة.
- بناء الشاشات المخطّطة (Risk/Strategy/Portfolio/Governance) — الـAPI غير منفَّذ.
- محرّر رسم بياني لمخطّطات سير العمل.
- تغيير أي شيء في `apps/api`.

## 5. تصنيف الطبقات

اكتُشف أثناء التصميم أن التصنيف الثنائي (حيّ/مخطط) خاطئ. `apps/api/config/features.php:6` يضبط `work_management` على `false` افتراضياً، و`EnforceWorkManagementFeature` يحرس 23 مساراً — ليس سجلات العمل وحدها، بل **نماذج العمل وسير العمل بالكامل**.

سلوك الخادم عند إطفاء العلم: **404 غير مُفصِح** للقراءات، **409 feature-disabled** للتعديلات — مُختبَر في `apps/web/e2e/walking-skeleton.spec.ts:128` و`:145`. هذا يفرض قاعدة تصميم: الوجهة المشروطة بعلم مُطفأ **تغيب تماماً**، بلا رابط معطّل ولا رسالة «غير متاح»، لأن الرسالة تنقض عدم الإفصاح المقصود.

مبدأ التجميع: **مساحة عمل واحدة لكل مجال، تبويب ثانوي واحد، قائمة ← تفصيل**. هذا هو المتعارف عليه في لوحات الإدارة، وهو ما يجعل «الموظفون» و«الوظائف» و«المسميات» تبويبات في `/organization` لا ثلاث وجهات في الشريط الجانبي.

**العمليات المخطّطة موسومة `📋 مخطط — API غير منفَّذ`** ومستثناة من بوابة التحقّق. لا تُسجَّل مساراتها في الراوتر قبل نزول الـAPI.

## 7. الثيم

من الفحص الفعلي للقالب:

- **Tailwind v4.2** — لا `tailwind.config.js`؛ الإعداد داخل CSS عبر `@theme` و`@custom-variant dark` وإضافة `@tailwindcss/vite`.
- ألوان **oklch**: `--primary: oklch(0.208 0.042 265.755)` · `--radius: 0.625rem`.
- `@radix-ui/react-direction` متوفّر ← RTL مدعوم.
- تقاطع المكدّس: React 19 ✓ · Vite 8 ✓ · TS 6 ✓ · TanStack Query 5 ✓ · lucide ✓.

**انحرافات مقصودة، ثلاثة:**

| الانحراف | السبب |
|---|---|
| `IBM Plex Sans Arabic` بدل Inter/Manrope | التطبيق عربي أولاً؛ خطوط القالب لاتينية والإبقاء عليها يعني عربية بخط احتياطي. الألوان والمسافات ونصف القطر لا تتأثر. |
| React Router 7 بدل TanStack Router | قائم ويعمل؛ التبديل تكلفة بلا عائد. |
| استبعاد Clerk وZustand وAxios | عندنا جلسة كوكيز، وTanStack Query يكفي كخادم حالة، وOrval يستخدم `fetch`. |
