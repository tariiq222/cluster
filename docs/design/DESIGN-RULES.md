## 0. القاعدة الحاكمة

**الثيم يُنسخ، لا يُعاد اختراعه.** توكنز القالب تُنقل حرفياً بقيمها الأصلية. أي رغبة في «تحسين» لون أو نصف قطر أو مسافة هي كسر للتوحيد، لا تحسين له.

## 1. الألوان والتوكنز

### 1.1 صفر ألوان حرفية

لا `#hex`، ولا `rgb()`، ولا `hsl()`، ولا `oklch()` مباشرة في أي ملف — عدا `src/styles/theme.css` وحده، وهو منسوخ من القالب.

```css
/* ✗ ممنوع */
.badge { background: #e6f4ec; }
<div className="bg-[#293b85]">

/* ✓ صحيح */
<div className="bg-primary text-primary-foreground">
```

### 1.2 التوكنز المسموحة

هذه القائمة مغلقة. لا تُضاف توكنز جديدة:

| المجموعة | التوكنز |
|---|---|
| السطوح | `background` · `foreground` · `card` · `card-foreground` · `popover` · `popover-foreground` |
| الدلالات | `primary` · `primary-foreground` · `secondary` · `secondary-foreground` · `muted` · `muted-foreground` · `accent` · `accent-foreground` · `destructive` |
| الحدود | `border` · `input` · `ring` |
| الشريط الجانبي | `sidebar` · `sidebar-foreground` · `sidebar-primary` · `sidebar-primary-foreground` · `sidebar-accent` · `sidebar-accent-foreground` · `sidebar-border` · `sidebar-ring` |
| الرسوم | `chart-1` … `chart-5` |
| الشكل | `--radius` (`0.625rem`) ومشتقاته `radius-sm/md/lg/xl` |

### 1.3 دلالات الاستخدام

| الحالة | التوكن |
|---|---|
| إجراء أساسي، عنصر تنقّل نشط | `primary` |
| إجراء ثانوي، خلفية هادئة | `secondary` |
| نص مساعد، تسميات، بيانات وصفية | `muted-foreground` |
| حذف، خطأ، تحذير مدمّر | `destructive` |
| تمييز عند التحويم/التحديد | `accent` |

**لا توكن للنجاح ولا للتحذير.** القالب لا يوفّرهما عمداً. الحالات الإيجابية/التحذيرية تُعبَّر عنها بـ`Badge variant="outline"` مع أيقونة `lucide` دالّة، لا بلون مخصّص.

### 1.4 الوضع الليلي

مجاني مع القالب عبر `@custom-variant dark` وصنف `.dark` على `<html>`. **لا تكتب `dark:` يدوياً على الألوان** — التوكنز تتبدّل تلقائياً. `dark:` مسموحة فقط لحالات نادرة مثل شدّة الظل.

## 2. التخطيط

### 2.1 أربعة أنماط فقط

كل شاشة تنتمي لواحد من هذه، وإلا تُرفض:

| النمط | متى | البنية |
|---|---|---|
| **قائمة ← تفصيل** | مجموعة كيانات يُفتح أحدها | `DataTable` + شريط أدوات ← صفحة كاملة للقراءة والإنشاء والتحرير والإدارة |
| **مساحة بتبويبات** | مجال واحد بعدة أوجه مترابطة | `Tabs` أفقية أعلى المحتوى، تبويب واحد نشط |
| **معالج** | عملية متعددة الخطوات لا رجعة سهلة فيها | خطوات مرقّمة + مؤشّر تقدّم + مراجعة قبل الالتزام |
| **لوحة** | تجميع للقراءة فقط | شبكة `Card` متجاوبة |

### 2.2 مستوى تنقّل ثانوي واحد

لا تبويب داخل تبويب. لا accordion داخل تبويب داخل قائمة. المستخدم يعرف موقعه من سطرين: الشريط الجانبي والتبويب.

### 2.3 لا accordion بطفل واحد

عنصر قابل للطي يحتوي عنصراً واحداً هو نقرة زائدة بلا مقابل. اعرضه مباشرة.

### 2.6 كل عمل في صفحة كاملة

الإنشاء والتحرير والإدارة والتفصيل تُفتح **صفحة كاملة** بمسار قابل للرابط (مثل `/tasks/new` و`/tasks/:taskId`) — لا `Sheet` ولا `Dialog` لنماذج الأعمال مهما كان طولها. الصفحة الكاملة تُحمل مباشرة وتُحدَّث دون الاعتماد على سياق الجدول، وتعطي المساحة اللازمة للبحث والتجميع والمراجعة.

**استثناءان وظيفيان فقط** يبقيان `Sheet`:

| الاستثناء | المكان |
|---|---|
| تنقّل الجوال | `app-sidebar.tsx` |
| المساعدة السياقية | `contextual-help.tsx` |

الحوارات تبقى للتأكيد على إجراءات خطرة فقط (`AlertDialog`/`Dialog` للتأكيد) — ليست نماذج.

### 2.7 صفحات الإضافة والتحرير الموجَّهة

كل صفحة إضافة أو تحرير على مسار قابل للرابط (`/documents/new`، `/tasks/:id/edit`، ...) تستخدم المكوّنات المشتركة في `apps/web/src/components/form-page-layout.tsx` و`apps/web/src/components/localized-file-picker.tsx` — لا شيفرة مكرّرة في كل شاشة.

| الغرض | المكوّن |
|---|---|
| نموذج كامل بوجهين (المدخلات + المراجعة/الإجراءات) | `TwoRegionFormLayout` |
| نموذج قصير مركَّز (تأكيد، خطوة واحدة) | `SingleRegionFormLayout` |
| قسم دلالي داخل أحد السطحين | `FormSection` |
| قائمة مراجعة `dl/dt/dd` | `ReviewSummary` |
| فتحة إجراءات المراجعة | `FormActionStack` |
| رفع ملف مترجم | `LocalizedFilePicker` |

قواعد ملزمة:

- **`TwoRegionFormLayout` هو الافتراضي.** كل صفحة إضافة/تحرير تبدأ به. الوجهان **أخوان** بنفس المستوى — لا سطح داخل سطح، ولا `max-w-2xl rounded-lg border p-4` جزيرة.
- **`SingleRegionFormLayout` فقط للنماذج القصيرة.** خطوة واحدة، حقول قليلة، لا مراجعة. الاستثناء: كتالوجات الأذونات والمعالجات متعددة الخطوات المعقّدة تستخدم `TwoRegionFormLayout` (مراجعة على الجانب).
- **سطحان مسطّحان.** الفواصل بين أقسام الوجه الرئيسي هي `border-t pt-6` عبر `divided` على `FormSection` — لا بطاقات متداخلة.
- **عمود واحد في الجوال.** شبكة `lg:grid-cols-[2fr_1fr]` تنهار تلقائياً إلى عمود واحد تحت `lg`؛ الوجه الرئيسي يبقى أولاً في ترتيب الـDOM.
- **المراجعة في الوجه الجانبي.** `<aside>` المعاينة والإجراءات في `TwoRegionFormLayout` يصبح `lg:sticky lg:top-20` لإبقاء الإجراء الأساسي مرئياً.
- **اللاقط المخصّص.** كل رفع ملف يستخدم `LocalizedFilePicker` — لا عنصر `<input type="file">` ظاهر، ولا تسمية إنجليزية افتراضية للمتصفح. الزر مرئي وقابل للوصول بالكيبورد، والـ`<input>` الحقيقي `sr-only` في الـDOM.
- **`lg:grid-cols-[2fr_1fr]`** قيمة اعتباطية وحيدة مسموحة وموثّقة هنا — نسبة العمودين ثابتة في كل الشاشات، فلا يُسمح بأي قيمة اعتباطية أخرى في صفحات الإضافة والتحرير.

### 2.4 وجهة أساسية واحدة لكل غرض

الغرض الواحد لا يُوصل إليه من مكانين في الشريط الجانبي. التكرار يجعل المستخدم يشك أنه في المكان الخطأ.

### 2.5 مصطلح المستخدم لا مصطلح المعماري

| ✗ | ✓ |
|---|---|
| كيانات الأشخاص | الموظفون |
| تعريفات العمل | نماذج العمل |
| نطاق الصلاحية الفعّال | مكان عملك الحالي |
| Idempotency Key | — لا يُعرض إطلاقاً |

## 3. الاتجاه (RTL)

### 3.1 خصائص منطقية حصراً

التطبيق عربي أولاً. أي أداة اتجاهية تكسره عند تبديل اللغة.

```
✗ ممنوع:  ml- mr- pl- pr- left- right- text-left text-right border-l border-r rounded-l
✓ صحيح:   ms- me- ps- pe- start- end- text-start text-end border-s border-e rounded-s
```

هذه القاعدة مفروضة آلياً في الـlint. الاستثناء الوحيد: أيقونة اتجاهية تعبّر عن اتجاه فيزيائي حقيقي (سهم تقدّم في شريط) — تُعلَّم بتعليق يشرح السبب.

### 3.2 التوجيه في الجذر

`dir="rtl"` على `<html>` عند العربية، و`DirectionProvider` من `@radix-ui/react-direction` يلفّ التطبيق كي تنقلب القوائم المنبثقة وأشرطة التمرير صحيحاً.

### 3.3 الأرقام والتواريخ

الأرقام بالخانات اللاتينية (`0-9`) في كلا اللغتين — بيانات الجداول تُقارَن بصرياً. التواريخ ميلادية بصيغة `YYYY-MM-DD` مع الوقت بجانبها عند اللزوم.

### 3.4 الخط

`IBM Plex Sans Arabic` — **انحراف مقصود عن القالب** (Inter/Manrope لاتينية). الألوان والمسافات ونصف القطر لا تتأثر.

## 4. الوصول والصلاحيات

### 4.1 المخفي ليس مُصرَّحاً به

إخفاء رابط أو زر تجميل لتقليل الضجيج، **وليس** ضابط أمان. الخادم هو الحارس الوحيد. لا تعتمد الواجهة على الإخفاء لمنع فعل.

### 4.2 الوجهة المشروطة بعلم تختفي تماماً

حين يكون علم ميزة اختياري مُطفأ (`tasks` مثلاً):

- **لا** رابط في الشريط الجانبي
- **لا** رابط معطّل رمادي
- **لا** رسالة «هذه الميزة غير متاحة»

الخادم يردّ **404 غير مُفصِح** عمداً كي لا يكشف وجود المورد. إظهار «غير متاح» في الواجهة ينقض هذا التصميم الأمني. المسار نفسه يُسجَّل في الراوتر ويردّ 404 كأي مسار مجهول.

### 4.3 403 و404 بنفس النص

المستخدم الممنوع والمورد المفقود يريان **الرسالة ذاتها حرفياً**. الفرق بينهما تسريب معلومة.

## 5. حالات الموارد

كل شاشة تجلب بيانات ترسم **السبع** حالات. لا واحدة تُهمل:

| الحالة | المخرج |
|---|---|
| `loading` | `Skeleton` بشكل المحتوى القادم وعدد صفوفه — لا دوّارة عامة |
| `ready` | المحتوى |
| `empty` | `EmptyState`: أيقونة + سطر يشرح + الإجراء الأساسي إن كان مُصرَّحاً |
| `forbidden` (403) | نص موحّد غير مُفصِح |
| `not-found` (404) | **نفس نص 403 حرفياً** |
| `conflict` (409) | `Alert` + سبب مقروء + زر إعادة المحاولة |
| `stale` (412) | `Alert` «تغيّر السجل» + زر تحديث يجلب النسخة الفائزة |
| `error` | `Alert` + زر إعادة المحاولة + معرّف الارتباط للدعم |

`stateFromError` في `src/api/http.ts` يشتق الحالة من الاستجابة. لا تعيد تصنيف الأخطاء داخل الشاشات.

## 6. البيانات والتنفيذ

### 6.1 مصدر المكوّنات

`src/components/ui/` مُولَّد بـ`npx shadcn@latest add`. **لا يُحرَّر يدوياً.** التخصيص يكون بالتغليف في `src/components/` لا بتعديل المصدر.

### 6.2 الجداول

`@tanstack/react-table` حصراً. **الترقيم بالمؤشّر فقط** (`cursor` + `next_cursor`) — الـAPI لا يوفّر أرقام صفحات ولا عدداً كلياً، فلا تعرض «صفحة 3 من 12» ولا شريط أرقام.

### 6.3 نداءات الـAPI

- العملاء مولّدون بـOrval من `docs/contracts/api/openapi.yaml`. `src/api/generated/` **لا يُحرَّر يدوياً**.
- **لا رؤوس HTTP خام في الشاشات.** `Idempotency-Key` و`If-Match` و`X-CSRF-Token` و`X-Correlation-ID` عبر `requestInit` في `src/api/http.ts` وحده، مُستدعىً من `src/api/hooks.ts`.
- أي تعديل يحتاج `If-Match` يمرّر `lockVersion` المقروء من الـETag. لا تخمين.
- `Promise.all` للطلبات المستقلة فعلاً فقط.

### 6.4 المكتبات المعتمدة

| الغرض | المكتبة |
|---|---|
| أيقونات | `lucide-react` |
| تنبيهات لحظية | `sonner` |
| نماذج | `react-hook-form` + `zod` |
| جداول | `@tanstack/react-table` |
| خادم الحالة | `@tanstack/react-query` |
| التوجيه | `react-router-dom` |
| رسوم | `recharts` |

**مستبعَد من القالب عمداً:** `Clerk` (عندنا جلسة كوكيز) · `Zustand` (خادم الحالة يكفي) · `Axios` (Orval يستخدم `fetch`) · `TanStack Router` (React Router قائم ويعمل).

## 7. الكتابة
