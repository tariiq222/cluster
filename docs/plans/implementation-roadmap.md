# خارطة التنفيذ السريعة

## النتيجة المطلوبة

بناء بقية النسخة المحلية المتكاملة خلال خمسة أيام عمل، بدءاً من W1.3. انتهت
W1.1 وW1.2 بالفعل ولا تدخلان في المدة. لا اجتماعات حالة، ولا ورش مواصفات، ولا
موافقات بشرية، ولا UAT يدوي داخل مسار التطوير. الكود والعقود والاختبارات تتقدم
معاً في شريحة رأسية واحدة.

الخمسة أيام timebox للتنفيذ وليست بديلاً عن الجودة: عند فشل التحقق تُصلح الشريحة
مباشرة، ولا يُنشأ تقرير أو اجتماع أو بوابة إضافية.

## خط الأساس

- W1.1 مكتملة ومثبتة بـ`make verify-w1-1` و`make verify-w1-1-local`.
- W1.2 مكتملة على `main` ومثبتة محلياً بـ`make verify-w1-2` ورحلة E2E المعزولة.
- W1.3 بدأت فعلياً في مساحات `work-1-3*`: capability catalog وRBAC persistence
  والعلاقات الإشرافية وسياسات الحقول وتدقيق الوصول الحساس.
- النشر على VPS ليس شرطاً بين الشرائح؛ ينفذ آلياً مرة واحدة بعد اكتمال البناء.

## برنامج الأيام الخمسة

| اليوم | الحزم المتوازية | المخرج القابل للتشغيل | الإغلاق الآلي |
|---|---|---|---|
| 1 | دمج أعمال W1.3، API القرار، علاقات الإشراف، واجهة إدارة الصلاحيات | `DecideAccess` موحد يطبق RBAC+ABAC على API والحقول مع تفسير القرار | اختبارات Authorization والعزل والحدود + بناء الويب |
| 2 | WorkDefinitions، Workflow، WorkRecords، Tasks | إنشاء نوع عمل ومسار، نشرهما، ثم تشغيل طلب ومهمة من البداية للنهاية | اختبارات الإصدار والثبات وOutbox وE2E للطلب |
| 3 | Documents، Notifications، Search، Reporting، Dashboard | مستند مفحوص، إشعار idempotent، بحث وتقرير ولوحة خاضعة للقرار نفسه | اختبارات الملفات والتسريب وإعادة التسليم + رحلة R1 كاملة |
| 4 | Strategy/Indicators وPortfolio/Projects بالتوازي، ثم ربط الأثر | خطة ومؤشر وقراءة ومحفظة ومشروع تحسين وأثر محسوب | اختبارات R2 الحسابية والحدود + رحلة R2 كاملة |
| 5 | Risk/Controls/Treatment/KRI، ثم تكامل النظام كله | خطر وتقييم وضابط وخطة معالجة وKRI وروابط R2 تعمل في React وLaravel | رحلات R1 وR2 وR3 + البناء + الحدود + فحص الوثائق |

يمكن أن تبدأ عقود R2 وR3 وقوالبها واختباراتها بالتوازي قبل يومها، لكن لا تُدمج
كتغييرات مكسورة. التبعية الوحيدة هي العقد المنشور الذي تستهلكه الشريحة التالية.

## ما حُذف من المسار

- ملاك الإصدار والمراجعين واللجان ومجالس الحوكمة والتوقيعات.
- W3.0 كمرحلة ورش مستقلة؛ تستخدم R3 قيماً افتراضية قابلة للتهيئة وتبدأ بالكود.
- UAT اليدوي والتدريب والتجارب الميدانية كشرط لإكمال التطوير.
- تقارير المخاطر الإدارية ونسب التقدم واجتماعات المتابعة.
- تجميد كامل للعقود قبل أول سطر كود؛ العقد يثبت مع الشريحة ويختبر ضد الانحراف.
- انتظار CI بعيد بين كل حزمة؛ الاختبار المستهدف محلياً يكفي للدمج المحلي، وCI
  النهائي يغطي المرشح الكامل.

## الضوابط التقنية التي تبقى

هذه ليست حوكمة بشرية؛ هي خصائص صحة وأمن داخل الكود:

- لا FK أو join أو ORM relation بين جداول موديولات الأعمال.
- قرار وصول واحد deny-by-default لكل API والبحث والتقرير والتصدير والتنزيل.
- تغيير الأعمال وOutbox في معاملة واحدة، والمستهلك idempotent.
- optimistic locking وIdempotency-Key للأوامر القابلة للإعادة.
- تشفير PII ومنع الأسرار في Git وفحص الملفات قبل الإتاحة.
- تثبيت السجلات الجارية على إصدارات التعريف والمسار المنشورة.

## طريقة الدمج السريع

1. كل حزمة تملك موديولاً أو مجلداً مستقلاً؛ الملفات المشتركة والعقود العامة تدمج
   مرة واحدة في نهاية اليوم.
2. تبدأ الحزمة باختبار سلوك واحد، ثم تنفذ أصغر vertical slice يجعله أخضر.
3. لا ينتظر backend الواجهة ولا العكس: يتفقان على snapshot صغير قابل للتوليد.
4. إذا تعارضت حزمتان، يحل التعارض في العقد أو الملف المشترك فوراً؛ لا تنشأ لجنة
   أو وثيقة قرار ما لم يتغير حد معماري دائم.
5. يسجل `active-delivery-status.md` مرة واحدة في نهاية اليوم، لا بعد كل commit.

## تعريف الاكتمال

- الرحلة المذكورة لليوم تعمل محلياً من React إلى MySQL/Redis والعودة.
- الاختبارات المستهدفة وحدود الموديولات والبناء خضراء.
- لا placeholder ولا endpoint وهمي ولا mock يثبت قاعدة أمنية.
- آخر يوم يمرر مجموعة التحقق المتكاملة ويسجل revision والنتيجة.

## ما بعد اليوم الخامس

إذا كانت المدخلات التشغيلية جاهزة، تنفذ مرحلة النشر الآلية في
`readiness-checklist.md`. الخصائص المتقدمة غير اللازمة للرحلات الأساسية، مثل أنماط
تصويت كثيرة أو عشرات القوالب واللوحات، تضاف بعد وجود النظام المتكامل ولا تعطل
النسخة الأولى.
