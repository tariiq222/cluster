# خطة R2 السريعة

## الهدف

بناء شريحة رأسية واحدة تربط خطة استراتيجية بمؤشر وقراءة ومشروع تحسين وأثر محسوب
خلال اليوم الرابع. لا مراحل موافقة بشرية، ولا ملاك إصدار، ولا UAT أو تدريب أو أعداد
إنتاج تجريبي. القيود الحسابية واختبارات العزل هي التي تقبل الشريحة.

## المخرج القابل للاستخدام

من React يستطيع المستخدم المخول أن:

1. ينشئ خطة بمحور وهدف ومبادرة ويفعّلها.
2. يعرّف مؤشراً ومستهدفاً موزعاً ويسجل قراءة دورية.
3. ينشئ محفظة وبرنامجاً ومشروع تحسين من قالب PDSA.
4. يسجل الإنجاز والميزانية الإدارية وصحة المشروع.
5. يربط المشروع بالمؤشر ويحسب الأثر دون تجاوز التحسن المرصود.

## حزم التنفيذ المتوازية

### R2-A Strategy + Indicators

- StrategicPlan وAxis وObjective وInitiative بإصدارات immutable عند التفعيل.
- Indicator وPeriod وTarget وMeasurement باتجاه ووحدة وبسط ومقام.
- تجميع افتراضي weighted average بحجم العينة، مع قالب معادلة محدود بلا كود حر.
- مستهدف تجمع ومستهدفات منشآت؛ validator آلي يمنع توزيعاً غير متسق.
- الحالات الضرورية: Draft وActive وRetired للخطة، Open وLocked للفترة.
- كل قياس يحتفظ بالمصدر والتوقيت، ولا يحتاج توقيعاً أو مراجعاً كي يدخل الاختبار.

القبول:

- نسخة خطة مفعلة لا تتغير؛ تعديلها ينشئ نسخة جديدة.
- توزيع 90% يرفض إذا كان التجميع لا يحقق 90% ويقبل عند تحققه.
- القراءة تحسب القيمة من البسط والمقام وتبقى UTC.
- مستخدم منشأة لا يقرأ تفاصيل منشأة أخرى.

### R2-B Portfolio + Projects

- Portfolio وProgram وProject وProjectTemplate وPhase وMilestone.
- ملكية المشروع بـ`organization_unit_id` ومشاركات بمعرفات فقط.
- حالات بسيطة: Draft وActive وOnHold وClosed وCancelled.
- قالب PDSA الافتراضي، وقالب عام قابل للتكوين من الواجهة.
- ProjectProgress وBudgetSnapshot بقيم plan وactual وforecast وvariance.
- صحة Green/Amber/Red محسوبة بقواعد قابلة للتهيئة؛ لا override يدوي في النسخة السريعة.

القبول:

- إنشاء مشروع من القالب ينشئ المراحل والمعالم ويثبت نسخة القالب.
- مجموع أوزان المعالم يجب أن يساوي 100%.
- الإنجاز يحسب من المعالم المكتملة، لا من قيمة يكتبها المستخدم.
- مشروع أحمر لا يختفي داخل متوسط محفظة أخضر.
- لا تكامل مالي ولا فواتير ولا أوامر شراء.

### R2-C Impact Link

- ProjectIndicatorLink يربط IDs المنشورة دون FK أو join عابر.
- يحفظ baseline وexpected impact وactual impact وفترة القياس والمنشأة المستفيدة.
- actual impact يحسب أو يسجل تحت قيد: مجموع الأثر المنسوب لا يتجاوز التحسن المرصود.
- يعرض رابط ثنائي الاتجاه في React عبر API كل موديول، لا عبر قراءة جدول الآخر.

القبول:

- تحسن من 80 إلى 86 يسمح بإجمالي أثر منسوب حتى 6 فقط.
- إعادة القراءة أو تغيير baseline تعيد الحساب وتترك snapshot سابقاً.
- حذف الرابط منطقي ويحافظ على السجل.

## ترتيب اليوم الرابع

| الفترة | التنفيذ | الناتج |
|---|---|---|
| البداية | تثبيت العقود الصغيرة والمigrations والاختبارات الحمراء لـR2-A وR2-B | حزمتان مستقلتان قابلتان للتنفيذ |
| الوسط | API + Domain + React لكل حزمة | خطة/مؤشر ومشروع يعملان منفصلين |
| النهاية | R2-C، seed، ورحلة المتصفح | هدف → مؤشر → مشروع → أثر في رحلة واحدة |

لا تنتظر R2-A اكتمال واجهة R2-B، ولا تتشارك الحزمتان جداول. نقطة الدمج الوحيدة
هي IDs والعقود المنشورة.

## التحقق المستهدف

- اختبارات Strategy الحسابية والإصدارات والعزل.
- اختبارات PortfolioProjects للقوالب والأوزان والصحة والميزانية.
- اختبار حدود يمنع الاستعلام العابر بين Strategy وPortfolioProjects.
- بناء Web واختبار route لكل حزمة.
- E2E بالعربية والإنجليزية للرحلة الكاملة.

## خارج R2 السريع

- DMAIC وFOCUS-PDCA وقوالب كثيرة؛ PDSA والقالب العام يكفيان الآن.
- workflows خاصة لاعتماد الخطط أو القياسات أو المشاريع.
- مدقق مستقل، لجان، مجالس، تقارير قبول، وتدريب.
- بيانات حقيقية أو 25 مؤشراً و10 مشاريع؛ seed صغير يثبت السلوك.
- تعديل يدوي لصحة المشروع أو أثره بما يتجاوز القيود الحسابية.

## تعريف اكتمال R2

- رحلة الخطة والمؤشر والمشروع والأثر تعمل محلياً من React إلى MySQL.
- القيود الحسابية والعزل وحدود الموديولات مثبتة آلياً.
- Read Models قابلة لإعادة البناء ولا تكتب في موديولات الأعمال.
- يسجل revision وأمر التحقق في نهاية اليوم الرابع.
