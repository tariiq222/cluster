# النسخ الاحتياطي والتحقق من الاستعادة قبل W27

هذا الإجراء إلزامي قبل تشغيل ترحيل حذف Work Management على قاعدة موجودة. لا يكفي نجاح أمر النسخ؛ يجب إثبات الاستعادة على قاعدة معزولة.

## 1. إيقاف الكتابة

أوقف API والعمال والـ scheduler أو ضع النظام في وضع الصيانة. اترك MySQL متاحًا للنسخ فقط، ثم سجّل وقت بداية نافذة الصيانة ورقم الإصدار الجاري.

## 2. جرد ما قبل الحذف

سجّل أعداد جداول Work Records وWork Definitions وWorkflow، وروابط `document_links`، وإسقاطات `search_index_entries` و`report_read_models`، وصفوف `outbox_events` غير المنشورة. احتفظ بالمخرجات مع تذكرة النشر.

## 3. إنشاء نسخة متسقة

استخدم أداة النسخ المعتمدة في البيئة مع snapshot أو transaction متسقة، وتشفير أثناء النقل والتخزين. احفظ معرّف النسخة غير القابل للالتباس، checksum، وقت الإنشاء، نسخة MySQL، ومدة الاحتفاظ.

لا تضع بيانات الاعتماد أو محتوى النسخة في مستودع Git.

## 4. اختبار الاستعادة

استعد النسخة إلى MySQL معزول لا يمكن للتطبيق الإنتاجي الوصول إليه. تحقق من:

- اكتمال الاستعادة دون أخطاء.
- تطابق الأعداد والجداول مع جرد الخطوة 2.
- قدرة نسخة التطبيق السابقة على الإقلاع والقراءة من القاعدة المستعادة.
- توثيق معرّف اختبار الاستعادة ونتيجته واسم المشغّل الثاني الذي راجعها.

## 5. السماح بالترحيل

ضع في ملف بيئة النشر ذي صلاحية `600`:

```dotenv
DESTRUCTIVE_MIGRATION_BACKUP_ID=<backup-system-id>
DESTRUCTIVE_MIGRATION_RESTORE_VALIDATION_ID=<restore-validation-id>
```

يرفض W27 العمل على قاعدة إنتاجية تحتوي الجداول القديمة إذا غاب أي معرّف. المعرّفات دليل تشغيلي وليست بديلًا عن النسخة أو اختبار الاستعادة.

## 6. التحقق بعد الترحيل

تحقق من غياب الجداول والصلاحيات المتقاعدة، وعدم وجود WorkRecord في البحث والتقارير وروابط المستندات النشطة، وسلامة Tasks وOrganization وIdentity وAuthorization. راقب أقفال MySQL، أقدم Outbox غير منشور، وأخطاء المستندات قبل إعادة المرور للمستخدمين.

## 7. الاسترجاع عند الفشل

لا تحاول تشغيل `down()`؛ W27 غير قابل للعكس. أوقف كل المكونات، أنشئ قاعدة جديدة، استعد النسخة المختبرة، ثم شغّل إصدار التطبيق السابق. لا تكتب فوق القاعدة الفاشلة حتى يكتمل التحقيق وتُحفظ أدلته.
