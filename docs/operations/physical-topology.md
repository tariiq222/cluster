# الطوبولوجيا الفيزيائية ومجالات العطل

## النطاق

تعمل جميع مكونات الإنتاج داخل مركز بيانات داخلي معزول. هذا نموذج مرجعي للتصميم؛ لا يحدد أصولاً أو شبكات أو أسماء فعلية.

```text
مستخدمون داخليون
  -> منطقة وصول داخلية / موازن داخلي
  -> Kubernetes: ingress ثم Web/API وworkers
  -> خدمات الحالة: MySQL | Valkey | OpenSearch للبحث | Loki للسجلات | S3-compatible storage | Vault
  -> نطاق منفصل: backup repository مع Object Lock
  -> نطاق إدارة منفصل: GitLab | Harbor | Nexus | GitOps controller
```

## مناطق الفصل

| المنطقة | المحتوى | ضابط الفصل |
|---|---|---|
| الوصول | مستخدمون وموازن داخلي | HTTPS داخلي فقط، لا وصول مباشر للخدمات |
| الإنتاج | تطبيق وخدمات حالة | Namespaces، RBAC، NetworkPolicy، موارد محجوزة |
| الإدارة | CI/CD ومرايا الحزم والسجل | وصول إداري محدود ومسار موافقة |
| النسخ والتعافي | مستودع نسخ مستقل | حسابات ومفاتيح وشبكة مستقلة عن الإنتاج |
| المراقبة | metrics وlogs وalerts | وصول قراءة محكوم وفصل احتفاظ السجلات |

لا يعتمد وجود مناطق التوفر أو رفوف متعددة إلا بعد تحقق البنية الفعلية. عند توفرها، توزع replicas المضادة للتقارب على أكثر من مجال عطل. لا يعد النشر على عقد متعددة بديلاً عن مستودع نسخ خارج نطاق عطل Kubernetes.

## السعة المرجعية

| البند | قيمة التصميم | معيار التحقق |
|---|---:|---|
| الحسابات | 5,000 إلى 20,000 | اختبار حجم بيانات مماثل |
| المستخدمون المتزامنون | حتى 2,000 | اختبار حمل قبل الإطلاق |
| API | `p95 <= 500ms` | قياس SLI تحت الحمل المعتمد |
| البحث | `p95 <= 2s` | قياس SLI تحت الحمل المعتمد |
| تأخر الفهرسة | `<= 60s` | فرق زمن المصدر والفهرس |
| فقد البيانات | `RPO <= 15 دقيقة` | تمرين PITR |
| التعافي | `RTO <= ساعتين` | تمرين استعادة ربع سنوي |

السعة التفصيلية لـCPU والذاكرة والتخزين وعدد عقد worker تحدد من نتائج اختبار الحمل والـcapacity review، ولا تفترضها هذه الوثيقة.

## قواعد التوزيع

- ثلاث عقد control-plane على الأقل عند استخدام RKE2، وتفصل عن أحمال التطبيق حيث تسمح السعة.
- تطبيق Web/API وworkers بعدة replicas؛ لا يعتمد scheduler على replica متعدد بلا leader election أو singleton واضح.
- تخصص MySQL وOpenSearch وLoki وValkey وObject Storage لعقد أو مجموعات عقد مناسبة مع anti-affinity حيث يتاح ذلك.
- توضع البيانات الدائمة على تخزين يحقق replication وسلامة مناسبة، مع مراقبة السعة والـIOPS.
- يبقى مخزن النسخ خارج عنقود Kubernetes وخارج نطاق عطل التخزين الأساسي بقدر ما تتيحه البنية.

## قبول الطوبولوجيا

- فشل عقدة تطبيق واحدة لا يوقف API أو workers الأساسية.
- فشل عقدة control-plane واحدة لا يمنع إدارة أو جدولة الكتلة.
- لا يوجد مسار شبكة تشغيلي إلى الإنترنت الخارجي.
- فشل عنقود Kubernetes لا يمنع الوصول إلى مستودع النسخ أو تنفيذ الاستعادة في بيئة معزولة.
