## القرارات الملزمة

- تستخدم المؤسسة منصة Kubernetes المدارة داخلياً إن كانت متاحة ومستوفية للتشغيل المعزول؛ وإلا فالتوزيع البديل هو `RKE2` بثلاث عقد control-plane.
- تعمل MySQL عبر MySQL InnoDB Cluster وOperator مع نسخ احتياطية قابلة للاستعادة إلى نقطة زمنية (PITR).
- يستخدم التخزين الكائني المتوافق مع S3، أو MinIO، مع Object Lock للنسخ الخاضعة للاحتفاظ.
- يستخدم Valkey عالي التوافر للـcache والطوابير، وOpenSearch للبحث الموجّه للمستخدم، وLoki للسجلات التشغيلية، وVault لإصدار شهادات PKI وإدارة الأسرار.
- تستخدم GitLab وHarbor وNexus كأدوار منصات داخلية، لا كإقرار بأسماء خدمات أو إعدادات منشأة فعلياً.
- البيئات المنفصلة هي `Dev` و`Test` و`Staging` و`Prod`.
- النشر GitOps فقط من artifacts موقعة ومصحوبة بـSBOM متحقق منه.

## معايير القبول التشغيلية

- `RPO <= 15 دقيقة` و`RTO <= ساعتين`، ويثبتان بتمرين استعادة ربع سنوي.
- التوافر الشهري لواجهة API هو `99.9%`، وAPI `p95 <= 500ms`، والبحث `p95 <= 2s`، وتأخر الفهرسة `<= 60s`.
- يثبت اختبار الحمل خدمة حتى `2,000` مستخدم متزامن قبل الإطلاق.
