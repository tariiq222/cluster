# منصة Dokploy وDocker Compose والنشر

> احتُفظ باسم الملف التاريخي لضمان استقرار الروابط، لكن Kubernetes لم يعد منصة التشغيل المعتمدة.

## قرار التوزيع

يعمل الإنتاج على خادم داخلي واحد يديره Dokploy. تُعرّف جميع الحاويات والشبكات والـvolumes وhealthchecks في حزمة Docker Compose مثبتة، ويستخدم Traefik لإنهاء HTTPS وتوجيه الطلبات. لا يستخدم Kubernetes أو RKE2 أو GitOps controller.

## فصل البيئات

| البيئة | الموقع | البيانات |
|---|---|---|
| `Dev` | أجهزة التطوير أو بيئة تطوير منفصلة | اصطناعية فقط |
| `Test` | CI أو Compose مؤقت | اصطناعية فقط |
| `Staging` | Compose مؤقت أو مشروع معزول عند الحاجة | اصطناعية أو منزوعة الهوية |
| `Prod` | خادم Dokploy الداخلي | بيانات تشغيلية محكومة |

لا يعد اختلاف أسماء مشاريع Compose عزلاً أمنياً كافياً. لا تشارك Prod أسرارها أو volumes أو بياناتها مع البيئات الأدنى، ولا تنسخ بيانات الإنتاج إليها بلا إخفاء معتمد.

## مكونات المنصة

| المكون | القرار |
|---|---|
| التطبيق | React وLaravel Web/API وworkers وscheduler ضمن Compose مثبت |
| قاعدة البيانات | MySQL على volume دائم؛ لا ينشر منفذه خارج شبكة Docker الداخلية |
| cache والطوابير | Valkey على شبكة داخلية بلا binding عام |
| التوجيه | Traefik عبر Dokploy؛ HTTPS هو مسار المستخدم الوحيد |
| الإدارة | واجهة Dokploy وSSH عبر VPN أو شبكة/عناوين إدارة مقيدة |
| الأسرار | خارج Git والصور، وتمرر من إعدادات محكومة على الخادم |
| النسخ | مشفر وخارج خادم الإنتاج وباعتمادات منفصلة |

## ضوابط النشر

- تنشر صورة OCI مثبتة بالـdigest مع Compose revision معروف؛ تمنع `latest` في الإنتاج.
- يسجل كل إصدار image digest وconfig revision ونتيجة migrations والفحوص والموافق.
- لا تنشر MySQL أو Valkey أو Docker API/socket أو Dokploy management على واجهة عامة.
- تعمل خدمات الحالة على شبكة داخلية، ولا يدخل Traefik إلا إلى خدمات HTTP المطلوبة.
- يسبق النشر تحقق Compose وhealthchecks ومساحة القرص والنسخة الاحتياطية المتاحة.
- ينفذ rollback إلى digest وconfig revision سابقين، دون down migration هدامة.

## حدود التوافر

الخادم الواحد نقطة فشل واحدة. إعادة تشغيل الحاوية لا تعادل HA، ولا تدعي المنصة استمرار الخدمة عند عطل الجهاز أو القرص أو الكهرباء أو الشبكة. يعالج الخطر بالمراقبة، وقطع/هدف بديل، وحزمة تشغيل قابلة لإعادة الإنشاء، ونسخ خارجية مجربة.

## قبول المنصة

- ينجح فحص حي يثبت أن المنافذ المسموحة فقط متاحة.
- ينجح نشر إصدار مثبت ثم الرجوع إلى الإصدار السابق مع فحوص صحة.
- تبقى خدمات الحالة والإدارة غير قابلة للوصول من مسار المستخدم.
- تنجح استعادة النسخ على هدف منفصل ضمن RPO/RTO المعتمدين.
- يثبت اختبار الحمل أن موارد الخادم تكفي للحمل الفعلي قبل الإطلاق.
