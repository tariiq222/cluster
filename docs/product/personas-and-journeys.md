# الشخصيات ورحلات المستخدم

## 1. الغرض

تحدد هذه الوثيقة الشخصيات الرئيسية التي تستخدم المنصة في الإصدارات الثلاثة، وتحدد رحلات المستخدم الجوهرية لكل شخصية مع معايير القياس. تمنع تباين الفهم بين فرق المنتج والهندسة والاختبار حول من نخدم وكيف نقيس نجاح الخدمة. تُحيل الوثيقة إلى قرارات الصلاحيات في `ADR-004` وإلى وثيقة تتبع المتطلبات لتفاصيل القياس.

## 2. قواعد تحديد الشخصيات

- الشخصية تمثل دوراً تشغيلياً ثابتاً، لا وظيفة إدارية مؤقتة.
- تُربط كل شخصية بقدرات المسار الافتراضي، وتُذكر الاستثناءات صراحة.
- تُقدَّر قيمة الشخصية من أثرها في تحقيق هدف مؤسسي محدد.
- تُذكر اللغات والمنطقة الزمنية والتقنيات المعتمدة لكل شخصية.
- تُمنع إضافة شخصية دون رحلة قابلة للقياس.

## 3. الشخصيات الرئيسية

### 3.1 الموظف Employee

| البند | الوصف |
|---|---|
| الدور | موظف داخل إدارة في التجمع أو منشأة |
| النطاق | إدارته وما يُشارك فيه |
| الهدف الرئيسي | إنجاز مهامه وطلباته دون ضياع الحالة |
| الألم الحالي | تشتت المتابعة بين البريد وExcel والورق |
| الأجهزة | كمبيوتر مكتبي رئيسي ومتصفح حديث، وجهاز لوحي عند التنقل |
| اللغة | العربية افتراضياً مع فهم إنجليزي أساسي |
| نسبة الاستخدام المتوقعة | 80% من إجمالي المستخدمين |

القدرات الأساسية:

- عرض المهام المسندة إليه وقائمة الانتظار.
- إنشاء طلب جديد من نوع منشور وإرساله ومتابعته.
- التعليق والمنشن وإضافة مرفقات.
- البحث ضمن نطاقه وتصدير ما يحق له.
- تحديث ملفه الشخصي ولغة الواجهة.

### 3.2 المدير المباشر Direct Manager

| البند | الوصف |
|---|---|
| الدور | مدير إدارة أو مدير منشأة |
| النطاق | إدارته ومرؤوسيه المباشرون |
| الهدف الرئيسي | اتخاذ قرارات سريعة ومتابعة الالتزام |
| الألم الحالي | ضياع الموافقات بين القنوات |
| الأجهزة | كمبيوتر وهاتف داخلي |
| اللغة | العربية مع فهم إنجليزي |

القدرات الأساسية للموظف مضافاً إليها:

- صندوق وارد للموافقات مع أزرار قرار سريعة.
- رؤية مهام الفريق وحالاتها.
- اعتماد أو رفض أو إعادة الطلبات وفق المسار.
- إسناد المهام لمرؤوسيه المباشرين.
- لوحة إدارة بمؤشرات مختصرة.

### 3.3 مسؤول التجمع Cluster Officer

| البند | الوصف |
|---|---|
| الدور | مسؤول في إدارة مركزية في التجمع |
| النطاق | إدارته داخلياً والمنشآت وفق العلاقة الإشرافية |
| الهدف الرئيسي | متابعة التجمع والمنشآت المصرح بها |
| الألم الحالي | غياب رؤية موحدة مراعية للعزل |
| الأجهزة | كمبيوتر مكتبي |
| اللغة | العربية والإنجليزية |

القدرات الأساسية للمدير مضافاً إليها:

- محدد نطاق من التجمع إلى القسم.
- رؤية مؤشرات مجمعة أو تفصيلية وفق القدرة الممنوحة.
- تحويل المؤشر إلى مشروع تحسين أو مهمة.
- لوحة مسؤول تجمع بمؤشرات حرجة.

القدرات الأساسية للمسؤول مضافاً إليها:

- قسم إدارة المنصة داخل الواجهة الموحدة.
- إدارة الهيكل والوحدات والمنشآت والعلاقات.
- إنشاء وتعديل أنواع الأعمال والمسارات.
- إدارة الحسابات والقدرات.

## 4. رحلات المستخدم الجوهرية

تعتمد القياسات أدناه على الإصدار الذي تظهر فيه الرحلة. الرحلة التي تمتد عبر إصدارات تُذكر مع الإصدار الذي تبدأ فيه.

### 4.1 رحلة الموظف: إنشاء وإرسال طلب

| البند | الوصف |
|---|---|
| الإصدار | R1 |
| الشخصية | الموظف |
| المسار | إنشاء طلب من نوع منشور → تعبئة حقول ديناميكية → إرفاق مستند → إرسال |
| النتيجة المتوقعة | ظهور الطلب في صندوق الجهة المستقبلة وإشعار للمرسل |
| معيار النجاح | ≥ 90% من المستخدمين ينجحون دون مساعدة في اختبار ميداني |
| الزمن المستهدف | P95 لإكمال الإرسال ≤ 90 ثانية |

### 4.2 رحلة المدير: اعتماد أو إعادة طلب

| البند | الوصف |
|---|---|
| الإصدار | R1 |
| الشخصية | المدير المباشر |
| المسار | فتح صندوق الوارد → استعراض الطلب → اتخاذ قرار → كتابة سبب عند الإعادة |
| النتيجة المتوقعة | انتقال الحالة وإشعار للمرسل وتسجيل في السجل |
| معيار النجاح | زمن الموافقة P95 ≤ 30 ثانية داخل الواجهة |
| الزمن المستهدف | زمن الدورة من الاستلام إلى القرار ≤ 24 ساعة عمل |

### 4.3 رحلة السوبر أدمن: إنشاء نوع عمل ومسار

| البند | الوصف |
|---|---|
| الإصدار | R1 |
| الشخصية | السوبر أدمن |
| المسار | إنشاء مسودة → إضافة حقول → تصميم نموذج → ربط مسار → تحقق → توقيع → نشر |
| النتيجة المتوقعة | إصدار منشور قابل للاستخدام يبدأ عنده السجل الجديد |
| معيار النجاح | نشر نوع عمل في أقل من 60 دقيقة من فتح المسودة |
| معيار التحقق | اختبار ميداني مع ممثل عن إدارة مستفيدة |

### 4.4 رحلة الموظف: التعامل مع مهمة

| البند | الوصف |
|---|---|
| الإصدار | R1 |
| الشخصية | الموظف |
| المسار | فتح المهمة → بدء العمل → إضافة تعليق أو مرفق → إرسال للاعتماد أو إغلاق مباشر |
| النتيجة المتوقعة | تحديث الحالة وسجل النشاط |
| معيار النجاح | عدم ضياع أي تعديل بعد فشل العامل |

### 4.5 رحلة الموظف: البحث ضمن النطاق

## 7. قواعد إضافية

- لا تُمنح شخصية قدرات خارج نطاقها التشغيلي حتى بتفويض، ويُمنع التفويض للأعمال الحساسة إلا بقيد إضافي.
- تُسجَّل تجربة كل شخصية في اختبار ميداني قبل كل إصدار.
- تُحدَّث الشخصيات والرحلات عند كل تغيير جوهري في النطاق أو في صلاحيات شخصية.
- يحق لأي دور تشغيلي العمل وفق شخصية `الموظف` كحد أدنى عند الدخول للنظام.
