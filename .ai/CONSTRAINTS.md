# Cluster Constraints

## قيود ملزمة

- لا توسّع نطاق المهمة تلقائيًا، ولا تعالج مشاكل مجاورة دون طلب صريح.
- لا تكسر حدود الموديولات أو ملكية الجداول والعقود.
- لا تنفذ SQL مباشرًا على جداول مملوكة لموديول آخر.
- لا تتجاوز محرك القرار المركزي للصلاحيات أو تعتمد على إخفاء الواجهة كحماية.
- لا تغيّر OpenAPI أو response envelopes أو error semantics ضمنيًا.
- لا تعدّل الملفات المولدة يدويًا.
- لا تضف Dependency أو خدمة خارجية دون حاجة مثبتة.
- لا تحول النظام إلى Microservices في المرحلة الحالية.
- لا تستبدل مكوّنًا أو تدفقًا قائمًا بإعادة كتابة واسعة عندما يكفي تعديل محدود.
- لا تغيّر سلوكًا أمنيًا أو بيانات حساسة دون Regression tests مناسبة.
- لا تنشئ UI عامًّا أو بأسلوب template يخالف `PRODUCT.md` و`DESIGN.md` وقواعد التصميم الملزمة.

## تغييرات عالية الخطورة

تحتاج خطة وتحليل أثر وتحقق موسع قبل التنفيذ:

- Authentication وSessions وCSRF.
- Authorization وRBAC/ABAC والنطاقات والتفويض.
- قواعد البيانات وMigrations والحذف والتعديل غير القابل للعكس.
- Outbox وWorkers والتزامن وIdempotency وlocking.
- عقود API وOpenAPI والعميل المولد.
- رفع وتنزيل الملفات والتخزين والفحص الأمني.
- Production وDeployment وSecrets والنسخ الاحتياطي والاستعادة.

## قاعدة التوقف

عند وجود غموض جوهري في الهدف أو تعارض بين المطلوب والقيود، لا تخمّن قرارًا منتجيًا أو معماريًا. اعرض التعارض والنطاق الآمن بدل تنفيذ تغيير واسع.
