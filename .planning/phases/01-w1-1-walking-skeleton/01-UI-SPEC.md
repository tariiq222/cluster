# Phase 01 — عقد تصميم واجهة المستخدم

> عقد مرئي وتفاعلي للمسار الرفيع: دخول حساب fixture، إرسال طلب منشور، قائمة «طلباتي»، وإشعار داخلي للمُرسل. لا يضيف هذا العقد إدارة هوية أو منشآت أو صلاحيات أو مسارات عمل.

---

## Design System

| الخاصية | القيمة |
|----------|--------|
| Tool | none — مكوّنات React أصلية ومركبة محلياً فقط |
| Preset | غير منطبق؛ لا يوجد `components.json` ولا حزمة واجهة معتمدة بعد |
| Component library | none — لا تدخل مكتبة أو registry قبل اعتماد intake/mirror/lockfile الداخلي |
| Icon library | none — استخدم رموز SVG محلية بسيطة داخل المستودع أو نصاً مرئياً؛ لا صور أو CDN أو مكتبات أيقونات خارجية |
| Font | `Tahoma, Arial, sans-serif`؛ أولوية خط نظام مثبت محلياً، ولا `@import` أو خط عام أو CDN |

**سبب الاختيار وحالة النظام:** لا توجد حالياً شجرة React أو CSS أو Tailwind أو shadcn في المستودع. التزمت الواجهة بنظام يدوي صغير كي لا تسبق قرار الحزم والمرايا الداخلية المؤجل. هذا يحقق قرار shell الموحد العربي افتراضياً ولا يقرر اعتماداً جديداً.  
**المصدر:** `01-RESEARCH.md` §Standard Stack و§Package Legitimacy Audit؛ `docs/adr/009-unified-react-shell.md` §Decision/§Operations.

### اللغة البصرية

واجهة إدارية صحية حكومية هادئة: أرضية عاجية باردة، مساحات عمل زرقاء رمادية منظمة، وشريط سياق منشأة رفيع بلون teal مؤسسي. لا تستخدم صوراً زخرفية أو تدرجات أو ظلالاً عائمة أو مؤشرات «مستشفى» مجازية. يعرّف شريط السياق الثابت **المنشأة الحالية من الجلسة**، ولا يكون محدداً قابلاً للتغيير في هذه المرحلة؛ ذلك يوضح نطاق العمل دون الادعاء بأن الواجهة تمنح أو تسحب صلاحية.

| السطح | العقد المرئي والتفاعلي |

| تأكيد الإرسال | بعد نجاح الاستجابة، استبدل النموذج بلوحة نجاح مع عنوان الطلب وزر «العودة إلى طلباتي». لا تدّعِ وصول الإشعار فوراً؛ تعرض حالة واضحة أنه سيظهر بعد معالجة الإشعار الداخلي. |
| الإشعارات | لوحة منبثقة من زر الإشعارات، بعرض 360px على سطح ثانوي. تعرض إشعار المُرسل نفسه فقط: عنوان قصير، وقت، وحالة قراءة. زر «تحديث» يعيد الجلب. لا تضف push أو WebSocket أو مركز إشعارات كامل. |

## Spacing Scale

القيم المعلنة (كلها مضاعفات 4):

| Token | القيمة | الاستخدام |
|-------|--------|-----------|
| xs | 4px | فجوات الأيقونة والنص، شريط الحالة |
| sm | 8px | فصل التسمية عن الحقل، padding عناصر مضغوطة |
| md | 16px | تباعد عناصر النموذج والصف، padding افتراضي |
| lg | 24px | padding بطاقات الدخول/النموذج وفواصل الأقسام |
| xl | 32px | فجوة الأعمدة وحواف المحتوى المكتبي |
| 2xl | 48px | فصل رأس الصفحة عن المحتوى الرئيسي |
| 3xl | 64px | padding عمودي لصفحة الدخول وفواصل الصفحات |

**قواعد تطبيق ملزمة:** الحقول والأزرار 44px كحد أدنى، وpadding أفقي 16px؛ مساحة المحتوى 16px على الهاتف و32px على سطح المكتب؛ الصفوف 16px عمودياً؛ لا تستخدم قيماً وسيطة عشوائية.  
**الاستثناءات:** حد الهدف التفاعلي 44×44px؛ حدّ 1px؛ حلقة تركيز 3px؛ هذه قياسات وصول وليست درجات spacing.

## سلوك الرحلة والحالات

### مسار المستخدم

1. تبدأ الواجهة في العربية و`dir="rtl"`. يبدل زر اللغة بين العربية/`rtl` والإنجليزية/`ltr` فوراً، ويحفظ الاختيار محلياً للجلسة التالية من دون أن يغيّر بيانات السجل.
2. بعد نجاح الدخول يعرض shell منشأة الجلسة فقط، ثم يجلب «طلباتي» والإشعارات المصرح بها من API. مؤشرات التحميل لا تكشف عدداً أو عنواناً قبل استجابة الخادم.
3. «طلب جديد» يفتح النموذج الفارغ. عند الإرسال، يمنع الزر النقر المتكرر، يبقى النص مرئياً مع «جارٍ إرسال الطلب…»/`Submitting request…`، ولا يمسح المدخلات قبل نجاح الخادم.
4. بعد الحفظ/الإرسال الناجح تظهر لوحة النجاح وتحدّث قائمة «طلباتي». الإشعار الداخلي أثر مشتق لاحق للـOutbox: تعرض لوحة الإشعارات البيانات التي أرجعها API فقط، ويظل زر «تحديث» متاحاً؛ لا تُظهر نجاح الإشعار كبديل عن نجاح حفظ الطلب.
5. تعرض القائمة سجلات الاستجابة المصرح بها فقط. إن عاد GET للطلب بـ403 أو 404، فاستبدل المحتوى برسالة المنع الموحدة أعلاه، ولا تعرض العنوان أو الوصف أو المنشأة أو سبب قرار الصلاحية، ولا تفرق بصرياً بين عدم الوجود والمنع.

### RTL/LTR والاستجابة

| العرض | العقد |
|-------|-------|
| هاتف أقل من 768px | رأس 56px وشريط سياق المنشأة أسفله. تنقل أفقي أسفل الشريط يحوي «طلباتي» و«طلب جديد»؛ لا sidebar ولا drawer. القائمة عمود واحد، النموذج بعرض كامل، ولوحة الإشعارات تتحول إلى bottom sheet بعرض الشاشة مع هوامش 16px. |
| لوحي 768–1023px | رأس 64px، تنقل أفقي داخل الرأس أو تحته، محتوى بعرض أقصى 720px للنموذج و960px للقائمة. لوحة الإشعارات 360px. |
| سطح مكتب 1024px فأكثر | رأس 64px، تنقل جانبي بعرض 240px، ومحتوى أقصى 1120px. يبقى النموذج 720px ولا يتمدد إلى عرض الصفحة. |
| الاتجاه | استخدم خصائص CSS المنطقية (`margin-inline`, `padding-inline`, `inset-inline`, `border-inline-start`) لا `left/right`. في RTL يكون التنقل الجانبي وموضع بدء الصف على اليمين؛ في LTR على اليسار. ينعكس ترتيب الكتل لا ترتيب الأرقام أو UUID أو كلمات المرور؛ اجعل تلك القيم `dir="ltr"` عند ظهورها تقنياً. |

### الوصول والدلالة

- اضبط `<html lang="ar" dir="rtl">` أو `<html lang="en" dir="ltr">` مع تبديل اللغة؛ كل صفحة لها `<main>` واحد و`<h1>` واحد.
- استخدم `<form>`, `<label for>`, `<input>`, `<textarea>`, `<button>` و`<nav aria-label>` الأصلية؛ لا تنشئ أزراراً من `div` ولا أيقونات غير موسومة.
- كل حقل مطلوب يملك تسمية مرئية، `aria-required="true"`، ورسالة خطأ مرتبطة بـ`aria-describedby`. بعد فشل الإرسال، انقل التركيز إلى ملخص الأخطاء ثم إلى أول حقل غير صالح عند اختياره.
- بعد نجاح الإرسال انقل التركيز إلى عنوان لوحة النجاح؛ وبعد إغلاق لوحة الإشعارات أو bottom sheet أعده إلى زر الإشعارات. لوحة الإشعارات تحبس التركيز على الهاتف وتغلق بـEscape وزر إغلاق مرئي.
- حلقة التركيز 3px بلون accent وخارج حدود العنصر، مرئية في كل الحالات. لا تعتمد على hover وحده. جميع الأهداف التفاعلية 44×44px كحد أدنى.
- استخدم منطقة `aria-live="polite"` لنجاح الإرسال وتحديث الإشعار، و`role="alert"` لأخطاء التحقق والفشل. لا تعلن loading المتكرر للقارئ.
- يدعم التصميم reflow حتى تكبير 400% بلا تمرير أفقي للمحتوى، باستثناء قيم تقنية `dir=ltr` عند اللزوم. لا تستخدم الحركة لتفسير الحالة؛ أي انتقال opacity/transform لا يتجاوز 150ms ويعطّل مع `prefers-reduced-motion`.

### حدود الصلاحية والخصوصية

- وجود/اختفاء رابط في التنقل تحسين تجربة فقط؛ API/Laravel هو المرجع. لا يمنح العميل وصولاً، ولا يفترض أن العنصر المخفي يعني المنع.
- لا تضع في الواجهة نصاً أو عداداً أو نتيجة بحث تكشف سجل منشأة أخرى. القائمة والإشعارات لا تتضمن «إجمالي المؤسسة» أو مرشح منشأة أو محدد نطاق في W1.1.
- لا تعرِض `reason_codes` أو `authorization_trace_id` أو `access_context` أو أسماء المنشآت الأخرى في رسالة المستخدم. تلك بيانات عقد/تدقيق خلفي وليست copy للمستخدم في هذه المرحلة.
- لا تسجل كلمة المرور أو bearer token أو محتوى الطلب في console أو toast أو حالة خطأ مرئية. لا تخزن بيانات الجلسة أو سجل طلبات منشأة أخرى في cache مشترك بالمتصفح.

## مراجع وقيود التنفيذ

- العربية الافتراضية، الإنجليزية، واتجاها RTL/LTR هي متطلب تسليم في هذه المرحلة؛ اختبر المسار نفسه لا مجرد تبديل نص الرأس. **المصدر:** `REQUIREMENTS.md` FR-R1-013؛ `ROADMAP.md` Phase 1.
- واجهة واحدة لا تعني حدود صلاحية في العميل. تحكم Laravel في العرض؛ يمنع 403/404 الموحدان تسرب العنوان وmetadata بين المنشأتين. **المصدر:** `docs/adr/009-unified-react-shell.md` §Security؛ `docs/architecture/overview.md` §9؛ `access-decision.schema.json`.
- النموذج ثابت ويُرسل `request` منشوراً بعنوان ووصف فقط؛ لا تنشئ موديول أو جدول `Requests` ولا شاشة مدير منفصلة. **المصدر:** `01-CONTEXT.md` D-11–D-12؛ `docs/architecture/overview.md` §6.
- الإشعار الداخلي للمُرسل هو أصغر أثر قابل للتحقق بعد الـcommit؛ يبقى derived، غير متزامن، وidempotent. **المصدر:** `01-RESEARCH.md` §System Architecture Diagram؛ `docs/architecture/overview.md` §10.
- لا تعتمد على CDN أو خطوط أو scripts أو APIs عامة. كل asset مرئي يضمّن محلياً أو يستخدم fallback نظامياً؛ لا تسجل مكتبة واجهة قبل الموافقة الداخلية. **المصدر:** `AGENTS.md` Constraints؛ `01-RESEARCH.md` §Package Legitimacy Audit.
