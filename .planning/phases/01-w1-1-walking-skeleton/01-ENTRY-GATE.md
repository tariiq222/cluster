# سجل بوابة الإدخال — W1.1 Walking Skeleton

**الحالة:** مفتوحة وحاجبة لاختيار product toolchain أو إغلاق بوابة النشر الدائم  
**النطاق:** تثبيت الدليل المطلوب قبل إنشاء product scaffold أو تثبيت product dependencies أو وصف امتثال تشغيلي دائم.

## حقول البوابة المصدّرة

### `approved-product-roots`

| الحقل | القيمة الحالية | الحالة |
|---|---|---|
| جذرا المنتج | لا يوجد جذر منتج معتمد بعد؛ الاقتراحان `apps/api` و`apps/web` ليسا اعتماداً | محجوب بقرار المالك |
| دليل الاعتماد | قرار مالك يحدد الجذرين اللذين سيحملان ملفات القفل وأدلة البناء | مفقود |

### `approved-dependency-bom`

| الحقل | القيمة الحالية | الحالة |
|---|---|---|
| قائمة الاعتماديات المباشرة | لا توجد اعتماديات منتج معتمدة أو إصدارات أو تراخيص مسجلة | محجوب |
| المصدر الداخلي | لا يوجد مرآة أو سجل داخلي معتمد ومسجل لكل artifact | محجوب |
| ملفات القفل | لا يوجد مسار معتمد لإنشائها أو حفظها أو التحقق منها | محجوب |

لا ينفذ أي تثبيت للحزم أو الصور قبل أن يسجل المالك، لكل dependency مباشر، الاسم والإصدار والترخيص ومصدر artifact الداخلي وprovenance وملف القفل المقابل.

### `internal-source-policy`

| القاعدة | الحالة |
|---|---|
| تدخل الحزم والصور عبر intake محكوم مع فحص المصدر والترخيص والثغرات قبل قبولها داخلياً | مطلوب؛ دليل التنفيذ مفقود |
| يبني المنتج ويعمل من مصادر داخلية ثابتة فقط، دون artifact mutable أو وصول خارجي | مطلوب؛ لا يجوز ادعاء تحققه بعد |
| تبقى أسرار الإنتاج ومواد التوقيع ومحتوى الطلبات خارج Git وسجلات CI وأدلة البوابة | إلزام أمني مستمر؛ دليل التشغيل المطلوب مفقود |

### `permanent-gate-status`

| البوابة | الحالة | شرط الإغلاق |
|---|---|---|
| النشر الدائم | **مفتوحة ومحجوبة** | قرار منصة معتمد، intake داخلي، مصادر artifacts، SBOM وتوقيع متحقق، حيازة مفاتيح، دليل قبول، ونشر معزول قابل للتدقيق |
| المسار التطويري | **مسموح فقط بعد اعتماد toolchain** | لا يتحول إلى دليل نشر دائم أو امتثال للبيئات المعزولة |

## سجل القرارات والأدلة D-01 إلى D-10

| القرار | المالك | الدليل المطلوب | الحالة الحالية |
|---|---|---|---|
| D-01 — حفظ العمل التطويري | مالك التطوير | سياسة تثبت أن المصدر وملفات القفل وأسرار التطوير القابلة للإلغاء فقط تُحفظ خارج بيئة الإنتاج، مع منع أسرار الإنتاج ومواد التوقيع ومحتوى الطلبات | مقيد بمسار work-preservation؛ لا دليل تشغيل مرفق |
| D-02 — مسار الإنتاج المعزول | مسؤول العمليات ومسؤول أمن المعلومات | مصفوفة تبين منع اتصال production بالإنترنت والمصادر العامة أثناء البناء والتشغيل والنشر، مع مصدر داخلي معتمد | محجوب؛ مصدر artifacts الداخلي غير معتمد |
| D-03 — انحراف منصة الخادم الأحادي | جهة CCB/المالك المعتمد | قرار انحراف يحدد الجهة والنطاق الزمني وضوابط التعويض وحالة هدف Kubernetes/GitOps | محجوب؛ لا يعد Docker/Compose أو الخادم الواحد دليلاً لـKubernetes/GitOps أو NetworkPolicy أو rolling rollback |
| D-04 — تخزين مرفقات ونسخ منفصل | مسؤول العمليات | إثبات خدمة MinIO داخلية منفصلة، وحدود فصلها عن الخادم الأحادي، وملكية مفاتيح التشفير | محجوب؛ الخدمة والمفاتيح والدليل مفقودة |
| D-05 — قاعدة بيانات أحادية أولية | مسؤول العمليات | اعتماد نطاق قاعدة البيانات الأحادية وحدودها وخطة التعويض، مع دليل أن ذلك لا يثبت HA | مقيد؛ MySQL واحدة لا تثبت HA أو تحمل فشل عقدة |
| D-06 — النسخ والاستبقاء | مسؤول العمليات | جدولة كل 15 دقيقة، احتفاظ 30 يوماً، نسخ مشفرة إلى التخزين المنفصل، وملكية مفاتيح التشفير | محجوب؛ لا يكفي وجود job أو ملف نسخ |
| D-07 — الاستعادة اليدوية | مسؤول النظام | runbook للاستعادة وrestore drill مقاس يسجل RPO/RTO والنتيجة والدليل | محجوب؛ لا يمكن ادعاء RPO/RTO قبل restore drill |
| D-08 — اعتماد حزمة الإصدار | مسؤول النظام | سجل موافقة حزمة يربط revision وartifact digest وSBOM ونتائج الفحص والتوقيع المتحقق | محجوب؛ آلية الاعتماد والتحقق غير مقررة |
| D-09 — intake والتوقيع وحيازة المفاتيح | مسؤول أمن المعلومات ومسؤول العمليات | تصميم معتمد للـintake والسجل/المرايا والتوقيع والتحقق وحيازة المفاتيح والنقل | محجوب؛ لا تُخمن الأداة أو الحيازة أو المصدر |
| D-10 — النقل والترقية والرجوع | جهة CCB/المالك المعتمد | مسار نقل معتمد، دليل نشر وrollback، وحسم علاقة الإجراء المضيف بهدف GitOps | محجوب؛ Docker/Compose ليس بديلاً معتمداً للنشر الدائم أو GitOps |

## حالة أدلة المتطلبات التشغيلية

| المتطلب | evidence status | الحد الفاصل |
|---|---|---|
| SEC-R1-001 — منع الخروج افتراضياً | محجوب | لا يثبت Compose أو الخادم الأحادي NetworkPolicy أو عزل الشبكة |
| SEC-R1-011 — SBOM وتوقيع | محجوب | يتطلب intake داخلياً وdigest وSBOM وتوقيعاً متحققاً وحيازة مفاتيح |
| OPS-R1-006 — rolling update وrollback | محجوب | يتطلب دليلاً مرحلياً لمسار دائم معتمد؛ الاحتفاظ بصورة سابقة وحده غير كافٍ |
| OPS-R1-007 — فصل البيئات | محجوب | يتطلب فصلاً حسابياً وشبكياً وصلاحياً موثقاً للبيئات |
| OPS-R1-008 — ترقية offline | محجوب | يتطلب intake وموافقة وتحققاً ونقلاً معتمداً |
| OPS-R1-011 — سجل صور داخلي | محجوب | يتطلب سجلاً داخلياً مركزياً وسياسة رفض المصادر الخارجية والوسوم المتغيرة |
| OPS-R1-012 — مرايا حزم داخلية | محجوب | يتطلب مرايا داخلية معتمدة ومسار إنشاء lockfiles قابل للتدقيق |

## حدود الدليل

- D-01 يحفظ العمل التطويري فقط؛ لا يثبت مسار production المعزول في D-02.
- Docker/Compose والخادم الأحادي وMySQL الواحدة، في D-03 وD-05، لا يثبتون Kubernetes/GitOps أو HA أو منع الخروج أو rolling rollback.
- MinIO والتشفير والنسخ كل 15 دقيقة لمدة 30 يوماً والاستعادة اليدوية، في D-04 إلى D-07، تبقى محجوبة حتى توجد الخدمة والمفاتيح وrestore drill موثق.
- لا يحتوي هذا السجل على credentials أو مواد توقيع خاصة أو محتوى طلبات.
